**The public portal is a Next.js 15 app.** Visitors browse published datasets and maps there. Contributors sign in to the same app to upload and submit datasets. The app calls the backend API with the user's token and never talks to the database.

## Route groups

Next.js route groups in brackets do not appear in the URL. They group pages that share a layout.

| Group | Who sees it | Examples |
| --- | --- | --- |
| `(business)` | Public visitors | Catalogue, maps, analytics, about, contact |
| `(auth)` | Signed-out users | Login, register, MFA, password reset |
| `(dashboard)` | Signed-in users and contributors | Dashboard, my datasets, upload, notifications, profile |

The full route list is generated in [Routes](/docs/reference/routes).

| Concern | Where it lives |
| --- | --- |
| Server data and caching | TanStack Query 5 hooks in `src/lib/hooks` |
| HTTP calls | `src/lib/api` |
| Forms and validation | React Hook Form plus Zod schemas in `src/lib/schemas` |
| Response shaping | `src/lib/adapters` |
| Types shared by pages | `src/types` |

## Notifications

- The bell reads the unread count and polls every **30 seconds**.
- A chime plays when the unread count goes up. The browser allows audio only after the first user click or key press.
- Each user can switch the chime off in **Profile, Security, Notification sound**. The setting lives in the browser (`localStorage`), not on the server.

## Permission-based display

- The UI hides buttons the user cannot use. The backend still enforces the same rule. **The UI check is a convenience, not the security boundary.**
- Contributors see upload and submit actions. Public visitors see only browse and download.
