**The database holds about 68 tables in PostgreSQL with PostGIS.** The core of the model is a dataset, the submission ticket that tracks its review, and the workflow actions that record each decision. Ingestion adds staging tables for the raw and resolved rows. The exact list is generated in [Database tables](/docs/reference/tables).

## Conventions

- Primary keys are UUIDs.
- Status columns hold text values from an enum in the entity file (for example `DatasetStatus`).
- Every review transition writes one row to `workflow_actions`. This is the audit thread.
- Soft delete is used where history matters. Hard delete exists only for datasets, behind a gate (see [Operations](/docs/operations)).

## Schema changes

1. Change the entity class in the module's `entities/` folder.
2. Generate or write a migration in `src/database`.
3. Run the migration against the development database and check the result.
4. Commit the migration with the code change. Never edit a migration that has already run in production.

**Exception: enum changes need care.** PostgreSQL cannot use a new enum value inside the same transaction that added it. Keep enum additions in their own migration.
