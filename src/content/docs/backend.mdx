**Every API request passes four global guards before it reaches a controller.** The guards run in registration order: JWT authentication, role check, capability check, then rate limiting. Each module owns one business area and its own database tables.

## Boot and entry points

| File | Role |
| --- | --- |
| `src/main.ts` | API entry. Requires `ROLE=api`. Sets the global prefix `api/v1`, CORS, the validation pipe, and Swagger (off in production unless `SWAGGER_ENABLED=true`). |
| `src/worker.ts` | Worker entry. Requires `ROLE=worker`. Starts queue processors and schedulers. No HTTP listener. |
| `src/app.module.ts` | Wires the API modules and registers the global guards. |
| `src/worker.module.ts` | Wires only the modules the worker needs. |

**Key point: guard order comes from registration order in `app.module.ts`.** Changing that order changes which check rejects a request first.

## Access control in code

- `@RequireAccess(roles, capability)` sits on each endpoint. It names the roles and the capability key allowed to call it.
- All capability keys are listed in [Capabilities](/reference/capabilities).
- A super admin passes every capability check. Other staff need a permission group that grants the key.

## Two authentication stacks

| Stack | Login route | Token secret | Used by |
| --- | --- | --- | --- |
| Public | `/api/v1/auth/*` | `JWT_ACCESS_SECRET` | Public portal and contributors |
| Admin portal | `/api/v1/admin/auth/*` | `JWT_ADMIN_SECRET` | Admin console and staff |

- Each stack signs its own tokens.
- **Exception:** public routes also accept admin-signed tokens, so a staff member can use the public portal with the admin login.

## Login protection

- **Lockout.** After `LOGIN_LOCKOUT_THRESHOLD` failed attempts, the account stays locked for `LOGIN_LOCKOUT_MINUTES`. Password failures and MFA code failures both count.
- **MFA methods.** TOTP (authenticator app), SMS (Termii), and email one-time codes. Backup codes use the `XXXX-XXXX` format.
- **Partial login.** When MFA is required, the login response sets `requiresMfa` and `mfaMethod`. The client then sends the code to finish login.

## Database access

- TypeORM entities sit in each module's `entities/` folder.
- Schema changes go through migrations in `src/database`. Do not change tables by hand.
- The full table list is in [Database tables](/reference/tables).
